# Design decisions

Defaults implemented in both engines and the batch reference. Each row names the switch that changes it and the evidence behind the default.

| # | Question | Proposed default | Switch | Evidence |
|---|---|---|---|---|
| 1 | Which timestamp is event time | Trading date + Trading time; fall back to system Date/Time when empty; parsed as naive local wall clock (epoch ms, no time-zone conversion) | fixed in `prep.py` | The official GC loader (Challenger `FinancialEventLoader`) does the same. 08–14.11.2021 is actually CET, although the brief says CEST. |
| 2 | Which rows are price events | SecType E or I, and Last parses to a number > 0 | fixed in `prep.py` and `scripts/filter.awk` | The Saturday file has 5,179 rows with Last = 0.000000 and trading time 00:00:00.000 (weekend resets). The official loader also drops zero prices. Gives the 59M "purged" events of the GC paper. |
| 3 | Close of a window | Price of the event with the largest (event time, arrival order) in the window | fixed | Brief: "last price event observed in window". |
| 4 | Window with no trade for a symbol | `skip`: no output, EMA carried unchanged | `--empty-window skip\|repeat` | GC solutions (FORTH, Noir) skip. On 3 synthetic days, `repeat` gives 1,555 advisories vs 374 for `skip`. |
| 5 | First-window advisory | Keep it (literal spec) | `--suppress-first` | Both EMAs start at 0, so every symbol's first window is a BUY: 300 of 374 synthetic advisories. On the real 08.11 day all 4,840 advisories are first-window BUYs; EMA100 needs about 8 hours to catch up, so real crossovers only appear from day 2. |
| 6 | Day boundaries | EMA state carries over nights and the weekend; windows align to midnight every day | fixed | 5 minutes divides 24 h, so epoch alignment equals midnight alignment. |
| 7 | When a window is evaluated | When the event-time watermark passes the window end; watermark = max event time - out-of-orderness bound (per partition, minimum across partitions) | `--out-of-orderness-ms` | Brief: "evaluated once the next window starts". Pick the bound from the out-of-order lag percentiles that `prep.py` writes to `stats/*.json`. On 08.11 the lag is p99 300 ms, p99.9 374 ms; a 300 ms bound gives 0 late trades, 0 ms gives 79. |
| 8 | Late events | Dropped and counted | `--out-of-orderness-ms`; `reference.py --late-bound-ms` applies the same rule | The diff against the batch reference shows exactly which results they change. Over the week, a 300 ms bound drops exactly 5,506 trades: a burst on 10.11 at 18:56 of index trades stamped 01:00:00.000 (about 18 h old; 1,812 index symbols, 1,441 in Paris and 371 in Amsterdam). Keeping them would change 683,775 EMA rows (37%) and about 840 advisories. |
| 9 | Subscriptions | Compute every symbol, emit only subscribed ones (file, one symbol per line) | `--subscriptions FILE\|all` | Brief 3.1(3). The GC platform asked for 5–19 lookup symbols per batch of 10,000 events. |
| 10 | Ticks whose timestamp is not their arrival time | Quarantine a tick when `sys_ts - event_ts > N` (stamped more than N before it arrived); off by default | `--quarantine-ms N` in `replay.py` (routes to `--quarantine-topic`), `engine.py` file mode and `reference.py` | Over the week, `event_ts - sys_ts` is within [-1 s, +1 s) for 99.89% of trades. One-sided at 1 h it flags exactly the 5,506 trades a 300 ms bound drops (any N from 1 s to 17.9 h gives the same set), so `reference.py --quarantine-ms 3600000` equals `out/week/reference-300` with no bound at all. The symmetric rule `abs(event_ts - sys_ts) > 1 h` would also flag 1,175 Xetra closing-auction trades (event 17:30, sys_ts 1–8.5 h earlier) that arrive on time: there the system time is stale, not the event time. Flink file mode has no `sys_ts` and does not quarantine. |
| 11 | Metadata | In-band: each metadata row that changes a symbol's isin or currency travels in the ticks topic at its feed position, stamped with the largest event time sent before it; with `--enrich` an advisory gets the isin,currency the feed had given when its window could first close (stamp < window end + bound) | `replay.py --with-metadata`; `--enrich` in the Flink job and `engine.py` Kafka mode; `reference.py --metadata-events` | Replaces a compacted topic loaded with the week's last value per symbol before the first tick, which let Monday's advisories see Friday's metadata. No symbol's isin or currency changes during the week: 5,479 rows are sent and one advisory changes (ICAVE.FR 10.11 07:20 BUY, whose metadata arrives 281,157 lines after its first trade, now has empty fields). Reference, Flink file mode at p = 1, 2, 4 and the Python engine's Kafka loop on drifting partitions agree on all 11,349 enriched advisories, and so do Flink at p = 1, 2, 4 and the Python engine draining the replayed topic through the broker (`out/meta-check`, 17.11). |
| 12 | Who subscribes | Compacted `subscriptions` topic, key `subscriber\|symbol`, value `subscribe`, `unsubscribe` or a tombstone; a symbol is emitted while it has at least one subscriber; EMAs are computed for every symbol regardless | `--subscriptions-topic` (Flink Kafka mode only); `--subscriptions FILE` stays the static option | Changes apply from the next window close after the operator reads them. The control topics hold event time back until their content at job start has been read, so symbols subscribed from the start get every window. |
| 13 | Delivery to subscribers | Engines emit one row per symbol and window; `trading/gateway.py` fans each row out through an inverted index symbol -> subscribers | `--sample N` writes the deliveries of N subscribers to files | Compute does not depend on the number of subscribers; only the gateway's work does. |
| 14 | Fault tolerance and delivery guarantee | Off, as before: no checkpoints, both Kafka sinks with delivery `none`, consumers `read_committed` (librdkafka's default). For a demo of recovery: `--checkpoint-ms 10000 --delivery exactly-once`, or `--delivery at-least-once` plus `collect.py --dedupe` | `--checkpoint-ms`, `--checkpoint-mode`, `--checkpoint-dir`, `--delivery` (Flink Kafka mode); `--isolation` (`collect.py`, `latency.py`, `topics.py count`), `collect.py --dedupe` | TaskManager killed after about 41% of `bench-week-q` (p = 2, 10 s checkpoints, `out/ft/recovery`): one restart from the checkpoint completed 4-5 s before the kill, failure detected after 11-17 s, restored after 21-27 s (10 s of it the restart delay). At-least-once: 136,655 duplicate EMA rows and 31 duplicate advisories, all equal to the kept row; exact after dedupe. Exactly-once: 0 duplicates and exact for `read_committed`; a `read_uncommitted` reader sees 133,369 + 13 extra rows from the aborted transactions, all equal to the committed rows. Overhead of 10 s checkpoints at p = 2 (3 alternated runs each): median job rate 931,635 (none), 1,093,809 (at-least-once) and 1,229,044 rec/s (exactly-once), ranges overlapping and drifting with the host; checkpoints take 0.3-0.4 s (p50), up to 1.3 s, and hold 7-20 MB. Latency to a `read_committed` reader (`SPEED=300`): p50 about 0.2 s without checkpoints or with at-least-once, 0.5-0.8 s with exactly-once and 1 s checkpoints, 2.6-3.1 s with 5 s checkpoints (p99 4.7-5.2 s); every run complete with 14,444 rows. |
| 15 | When a window closes if no tick follows it (evenings, nights, end of data) | Off: only ticks move event time. Every partition trades until 22:25-22:35, so each evening the windows ending 22:30, 22:35 and 22:40 close with the next morning's first ticks, about 8.5 h later live; the last evening's never close in an unbounded Flink job (the Python engine flushes them when it stops) | `replay.py --heartbeat-ms N` (heartbeat to every partition carrying H = feed clock - `--heartbeat-margin-ms`, default 1000; `--heartbeat-tail-ms`); `HEARTBEAT_MS`, `HEARTBEAT_TAIL_MS`, `MAX_GAP_MS` in `latency_run.sh` | Brief: "evaluated once the next window w_i+1 starts"; whether that needs a later tick is open. `withIdleness` cannot help: all partitions go quiet together and an all-idle source holds its watermark. The feed clock is the largest `sys_ts` replayed; `trading/heartbeat_check.py` over the week at 300 ms: 0 ticks in an already closed window for any margin from 0 to 2 s; at 1 s, 5,106 ticks have event_ts < H - 300 ms, all Xetra closing-auction trades 17:30-17:31, each already that far behind the newest replayed event time (from a 700 ms margin up, heartbeats add none). 08.11-09.11 at 600x without gap compression (`out/heartbeat`): without heartbeats the 3 evening windows (97 rows) are emitted 51 s after the replay passed their end + 300 ms; with heartbeats every 1 s, Flink p = 2 emits them after 132-258 ms and the Python engine after 164-184 ms, the last evening's after 46-278 ms with a 5 min tail, and both outputs equal the reference (without heartbeats Flink lacks the last evening's 97 rows). |
| 16 | Kafka partitioner | CRC32 of the symbol (librdkafka default), off-the-shelf; busiest of 4 source readers gets 29.5 % of the week's ticks | `replay.py --partition-map FILE` from `trading/partition_map.py` | A map built from 08.11 counts balances 09.11-12.11 to within 1.5 % (busiest reader 25.1 % at p = 4 on 09.11, results identical to the reference); the keyed stage stays at Flink's key-group split (27.4 %). Throughput effect not resolved on the loaded laptop (`out/partitioner/summary.md`). |
